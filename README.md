# CyberChain Security Platform

This application is a high-fidelity, interactive **Threat Operations Center** and **Forensic Laboratory**. It uses an immersive 3D technology stack to visualize cryptographic transactions, simulate real-world cyber attacks against centralized pipelines, and apply blockchain resilience algorithms to automatically heal corrupted financial records.

> [!NOTE]
> The primary objective is shifting the user experience from reading passive logs to actively playing the roles of *both* the Hacker and the Threat Analyst in real-time.

---

## ⚡ 1. The Threat Operations Center

The centralized dashboard is designed for triggering orchestrated scenarios and visualizing catastrophic data alterations.

### Live Attack Vectors Orchestration
We use an automated **Scenario Engine** to execute complete story-driven attack journeys:
- **MITM Interception (Man-in-the-Middle):** The engine intercepts a transfer in real-time before network persistence, visually mutating the value. 
- **Double Spending Injection:** Forcefully injects duplicate intentions to spend digital reserve prior to network lock.
- **Ledger Tampering Data Drift:** Corrupts raw, settled block data in the database directly, simulating a hacked centralized disk.

### The 3D Multi-Branch DAG Topology
The core tracking visualizer is a powerful `React Three Fiber` scene designed to simulate a massive network topology.
- **Staggered Multi-Branch Networking:** The 3D scene algorithmically staggers and branches blocks outwards on the Z/Y axes, simulating the complex reality of multiple user-to-user branch transfers natively.
- **Physical Deep-Inspection:** Clicking *any* floating 3D block overlays a deep-analysis modal interface. This allows the user to inspect the exact `SHA-256` string hashes or even manually Tamper the block directly.
- **Dynamic Recovery Healing:** When launching a tactical recovery algorithm, the compromised (red) blocks in the 3D viewer spin and pulsate with an intense green "healing" aura until rewritten, visually communicating the network fixing itself.

## 🔐 2. Architectural Security Tactics

If the "Centralized" system fails and is hacked, switching to the **Blockchain Guard** opens access to active recovery algorithms:
1. **Recalculate Hash Tree (Proof-of-Work):** Explicitly accepts the hacked block as the "new truth" but re-mines the entire cryptographic chain linearly from that node forward so the math checks out again.
2. **Network Consensus Override (PBFT):** Represents Practical Byzantine Fault Tolerance. The network polls healthy virtual nodes to identify the corrupted data difference, dynamically overrides the hacker's data, and resets it to the original network snapshot.
3. **State Rollback:** Permanently drops the untrusted block entirely, destroying its links and severing pending transactions like orphans.

## ⛏️ 3. The Forensic Sandbox

To understand the core math behind the 3D visualization, the **Proof-of-Work Mining Protocol Sandbox** isolates the hashing algorithm. 

Instead of abstracting the security, users physically calculate block trust manually:
- **Ledger Data String:** A raw string injection representing who sent what (e.g., `System Admin -> Aarav Sharma | 1200 | settled`).
- **Cryptographic Engine:** Typing a single new character immediately mutates the live SHA-256 hash beneath it dynamically.
- **Asynchronous Mining Loop:** Once the data is hacked and the hash "shatters", users click **Mine**. A non-blocking asynchronous `while-loop` engine fires up, rapidly generating random `Nonce` variables until the hash meets the exact Difficulty Target (e.g. `000`). It visually flashes through computations like authentic mining rigs!
